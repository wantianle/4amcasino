参考端桌面：布局与动画规格

这是一份可审阅、可点击播放的行为规格，不是主题样板。左侧保留参考证据，右侧给出目标结构；所有时间均标注为视频测量或估算。

阅读结论：参考视频的跑马场景是“翻前六人桌，翻后单挑”；牌桌不放位置标签、不放 showdown 徽章，国旗也不做。下注区固定在右下角，纯数字表示积分，BB 只在明确需要时带后缀。

05 / 代码核实：发牌动画现状

结论：用户说“仍然从上往下落下三张”基本成立，但不是因为调用方缺少 slide。

  • DealCard.tsx:23–28 已定义 `fly | slide | flip`；slide 本意是“平移、保持平面”。
  • DealCard.tsx:89–101 用牌堆 rect 与目标 rect 计算 dx/dy，所以动画路径是任意二维直线；若牌堆在上方，视觉上就是斜向 / 下落。
  • TablePage.tsx:2237–2244、2263–2269 公共牌确实传了 `mode={index < 3 ? 'slide' : 'flip'}`，并按 FLOP_STAGGER_MS = 160 错峰。
  • 因此当前行为已经比“全部从上落下”更接近目标，但仍未实现参考图要求的“flop 三张先横向拉出”，差别在 DealCard.tsx 的 slide 路径约束，而非 `TablesPage.tsx` 参数。

06 / 主题结构

共用骨架

结构只保留语义：.table / .seat / .board / .panel / .timeline。主题只替换 CSS custom properties，交互和动画不复制。

[data-theme="green"] → felt / accent / border
[data-theme="red"] → felt / accent / border

不要让主题改变的东西

  • 右下操作区锚点和滚轮行为
  • 牌面顺序、座位层级、公共牌 5 槽结构
  • 时间轴、reduced-motion 可读性

07 / 需要用户确认的问题

  1. “先平移拉出三张”是指三张同时从牌堆横向展开，还是第一张到位后依次推出另外两张？视频能确认是逐张错峰，但横向路径的最终方向需要产品定稿。
  2. “翻转两张”是否严格指 turn 与 river 都必须有 3D 背面翻转，还是只要求原位 reveal；参考帧能看出 reveal 结果，不能确认背面过渡细节。
  3. 跑马实时胜率气泡的数据刷新频率、是否显示每个玩家（包括弃牌者），以及并列 / 多跑时的文案格式。
  4. 结算“所有筹码先进筹码堆”中的筹码堆是中央总池，还是每个下注点先各自归并再进中央池；视频分辨率不足以判定完整路径。
  5. 右侧 “Total Prize / My Points / My Prize” 仅属于锦标赛桌。现金桌是否完全隐藏？目标产品当前数据来源是什么？
  6. 下注区暗红色是全套三按钮统一红，还是 Bet 保持更亮的强调红；BB 后缀是否由桌级开关控制？
  7. 等级徽章的数字来源与位置是否保留；国旗按现有裁决不做。

08 / 诚实清单与不该动的部分

证据等级

  • 直接看出：右下下注区、比例按钮 / slider、参考端绿色桌、彩色座位框、多跑双 board、筹码飞行与 WIN 画面。
  • 测量：视频帧率 29.75fps；flop 关键帧约 4.158–4.628s；跑马 Split Options 约 16.5–21.0s；结算约 30.18–30.92s。
  • 推断 / 估算：白闪 0.85s、聚拢 0.25–0.45s、下注飞行 0.48s；这些应作为体验初值，不是素材原始参数。
  • 素材不足：精确贝塞尔曲线、聚堆的完整中间路径、胜率刷新协议、锦标赛信息列在当前产品中的数据契约。

判断“不该动”

  • 不动 `gg-l0-visual-baseline.html` 与 `gg-l1-phone-geometry.html`：它们是判据夹具。
  • 不动已通过碰撞验证的座位环 / 手机缩放 / 多跑 5 槽宽度；动画应在现有几何内完成。
  • 不复刻左下工具按钮；产品按自己的功能设计。
  • 不在牌桌上添加 SB / BB / BTN / MP / CO 位置标签；那属于历史记录页。
  • 不添加 showdown badge；用户已明确没有。
  • 不添加国旗；已有项目裁决明确不做。
