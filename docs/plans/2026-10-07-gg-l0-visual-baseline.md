# GG 牌桌 L0 视觉基线夹具

## 交付物

- 夹具：`docs/fixtures/gg-l0-visual-baseline.html`
- 权威结构依据：`docs/plans/2026-10-06-gg-table-reference.md`
- 参照素材：`docs/media/gg-reference/`
- L0 初版没有修改 `apps/web/src/widgets/table/`；后续 L1a 已按计划修改几何消费与手机表面分支，本文件保留该历史说明。

选择独立 HTML 而不是 dev-only React 路由，原因是 L0 的职责是基线与判据：它不应引入登录、房间状态或产品代码耦合；文件可离线打开、可审查、可作为后续 L1–L7 的固定验收页。真实当前渲染仍必须由 Vite 页面截图提供，夹具不会用静态假图冒充产品截图。

## 逐张参照结论与量化目标

| 对象   | 参照结论                                              | L0 gate                                                                                 |
| ------ | ----------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 桌体   | 桌面横椭圆；手机竖椭圆/钟形向下延伸                   | 桌面外缘宽高比 `1.65:1 ± 0.10`；手机高宽比 `≥ 1.35:1` 且长轴垂直                        |
| 座位   | 圆头像挂在外缘；深色信息胶囊紧贴头像下方并略压桌沿    | 头像直径为桌宽 `9% ± 2%`；胶囊中心与头像中心横向偏差 `≤ 10%` 头像直径；名字上、筹码下   |
| 弃牌   | 两张牌背插在头像后方，顶部高出头像，和头像明显重叠    | 牌背层级低于头像；交集面积 `> 0`；牌背顶端高于头像顶端。**交集不得为 0 作为通过条件。** |
| 摊牌   | 牌浮在头像上方，不挡脸                                | 牌层级高于头像，但脸部可见区域无遮挡                                                    |
| hero   | 桌面在 felt 内下缘、头像/pod 上方；手机放大到底部中央 | 手机 hero 中心距桌中心横向 ≤ `5%` 桌宽，牌组宽 ≥ 桌宽 `30%`                             |
| pot    | 桌面中央上方文字胶囊；手机筹码堆+数字                 | 桌面中心 x `50% ± 3%`，不以筹码图标替代；手机必须有筹码堆和金额                         |
| 公共牌 | 中央一排 5 张，手机更大                               | 摊牌/river 恰好 5 张单排；preflop 恰好 0 张                                             |
| 下注   | 下注者与中央之间 felt 内的筹码堆+金额                 | 堆位于两者连线上；金额紧邻；不能只显示名牌数字                                          |
| D      | 黄色圆盘在 felt 内，不贴座位；桌面无 SB/BB 徽章       | D 在 felt 内，离任一头像至少 `1.5×` 头像直径；SB/BB 徽章数量为 0                        |

目标是可测量关系，不是“看起来像”。尤其不能用通用矩形不重叠替代“谁盖谁、谁在桌内/桌外、相邻关系”。

## 夹具用法与截图流程

```sh
# 仓库根目录；只启动，不改产品代码
npm run dev -w @4am/web -- --host 127.0.0.1 --port 4173
```

1. 浏览器打开 `docs/fixtures/gg-l0-visual-baseline.html`（可直接 `file://` 打开；若浏览器禁止本地图片，用任意静态文件服务器提供 `docs/`）。
2. 在同一浏览器打开真实 `http://127.0.0.1:4173/room/<真实房间 id>`，完成登录。
3. 桌面截图用 `1176×888` viewport；手机截图用 Chrome DevTools `390×844`。必须等待真实渲染稳定后截图，记录 viewport、提交 SHA、状态（preflop/弃牌/摊牌/hero/pot/board/bet/D）。
4. 把真实截图并排与夹具中的两张参照图比对。夹具中“当前渲染”面板刻意显示证据占位，不伪造截图。
5. 收尾关闭 Vite，确认 `4173` 已释放。

本轮环境没有可用的登录身份和真实房间 id，因此没有运行前端、没有生成“当前渲染”截图，也没有把占位证据误报为验收通过。这是待补证据，不是产品通过。

## L1 建议

**先改 `PHONE_CANVAS` 与手机桌体的竖长比例，并用本夹具的桌面/手机同 viewport 关系重新量测；理由是它决定所有手机座位、公共区、下注筹码和 hero 的空间预算，先修几何才能避免在错误容器里反复调座位。**

## L1a oracle 补强与本轮契约

本轮 L1a 只负责几何契约；L0 仍是“artifact 完成 / 证据待补 / 未通过”，以下数值不是视觉验收的替代品。

### 测量边界

- 桌体比例统一量 **可见 rail/felt 主外缘 bounding box**，即 `rim` 层；不量地面 shadow，不用 shadow 的外溢改变比例。
- `inset` 是实际 playing surface，用于公共区、下注筹码和 D 的“在 felt 内”判定。
- 400×560 的手机设计画布比例为 `560 / 400 = 1.40`；当前手机 rim 为 86%×85%，实际测量比例为 `560×.85 / (400×.86) = 1.382`，达到 oracle 要求的 `≥ 1.38` 余量目标。

### 9 人碰撞 / 可见性 gate

对 `SEAT_COUNT = 9` 必须用完整 9 座计算，而不是把 6 座参照图的间距直接外推：

- 九个 seat anchor 都必须落在 viewport 内；手机不得依赖滚动才能看到任一座位。
- 相邻头像圆的 bounding circle 交集面积必须为 `0`；相邻 pod 的可读文字矩形交集也必须为 `0`。
- 任一 pod 不得遮住公共区；牌背/摊牌牌不得遮住相邻座位。
- 手机最终缩放 `k >= K_FLOOR (0.55)`；若内容不能满足，则必须调整手机几何预算，不能偷偷缩小到 floor 以下。
- 以上是计算 gate，不用“整体看起来不挤”替代。

### 关系的可计算定义

- pot：`pot.centerY < table.centerY - 0.05 × table.height`；“中央上方”不再是软描述。
- 信息胶囊：胶囊顶部到头像底部的垂直间距在 `[-0.20D, +0.10D]`，其中 `D` 是头像直径；负值表示胶囊压入/压着桌沿，超过 `+0.10D` 视为脱离头像。
- “压桌沿”：胶囊与 rim 的交叠高度必须 `≥ 0.10 × 胶囊高度`，同时胶囊中心仍在头像中心正下方 ±`0.10D`。
- 弃牌牌背：与头像交集面积必须 `≥ 5%` 头像面积，或交集高度 `≥ 0.15D`；仅 1px² 不算有效重叠。
- 摊牌不挡脸：牌面矩形不得与头像内圆中央 60% 安全区相交（安全区为以头像圆心为中心、半径 `0.30D` 的圆）。
- 下注连线：从 seat anchor 到桌中心的线段；下注堆中心到该线段的垂距必须 `≤ 0.15 × table.width`，并且下注堆落在 inset 内。
- D：不得与任一头像、胶囊、公共牌、pot、下注堆相交；到最近 seat anchor 的距离 `≥ 1.5D`；不得落在 rim 外缘安全带。

### 状态补强

- preflop 必须同时满足：公共牌数量为 `0`，且中央不存在残留发牌牌堆/牌背。
- board 数量 gate：preflop=`0`、flop=`3`、turn=`4`、river=`5`；多 run board 按每一 run 独立验收，每行最多 5 张且各行不遮挡 pot/座位，不能把多 run 合并后误判为一行 10 张。
- L1–L4 只验结构、几何、层级、相邻关系；不验颜色材质。绿 felt 参照不能推断红 felt 通过。L5 才验 GG 红 felt，并且必须有**手机红 felt**证据，不能用桌面红 felt 推断。

### L1a 变更记录

- `PHONE_CANVAS`: `548×410` → `400×560`；高宽比 `0.75` → `1.40`。
- phone seat ring: `rx 44 / ryNear 41 / ryFar 33` → `rx 36 / ryNear 39 / ryFar 26`；长轴空间给 9 座的纵向邻接与中心区让路。
- `PHONE_FELT` 新增：shadow=`88×86`、side=`86×82`、rim=`86×85`、inset=`82×78`；只由手机路径消费。`PHONE_RIM_RATIO` 在几何模块运行时断言 `≥1.38`。
- `BET_RING_PHONE`: `31 / 25 / 7 / 42` → `24 / 24 / 9 / 28`（rx / near ry / far ry / bottom nudge）。
- `SEAT_ANCHOR_PHONE` 保持 `1.01 / 1.01 / 12`，但现在由新的竖向 canvas 和 `centerColumnBudgetPx()` 重新计算，不复用桌面 anchor。
- `CENTER_COLUMN` 的百分比保持不变；它是共享语义，手机预算由 `centerColumnBudgetPx(PHONE_CANVAS, SEAT_ANCHOR_PHONE, ...)` 派生，避免复制第二份预算常量。

## 诚实清单 / 需 oracle 裁决

- 本轮没有登录凭据和真实房间 id，无法生成合规的当前产品截图；L0 夹具已落地，但视觉基线尚未被截图验收。
- 手机参照 `gg-mobile-2026-appstore-02.jpg` 是 WSOP 主题绿 felt，而默认产品主题已拍板为 GG 红 felt；oracle 需要确认验收时是否只比结构/比例，还是要求另备红 felt 手机图作为材质证据。当前建议：L1–L4 比结构，L5 单独比红 felt 材质。
- 参照图主体是 6 人，但产品决策为 9 人。当前 gate 采用“结构同构 + 9 个座位可见”，不把参照人数当成产品人数；如 oracle 要求 9 人的官方截图证据，需要另指定来源。
- ClubGG 目录部分图片是营销/产品页，不是牌桌；它们只作 hero/产品语境参考，不能作为桌形或座位几何 gate。
